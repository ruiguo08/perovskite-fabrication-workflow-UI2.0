领域状态色（Domain State Colors）

这四组颜色不是装饰——它们是写进这个应用底层的状态语言，第 0 期之前就存在， 并已写进设计提案的“保留项”。这也是我在“切 Notion”讨论里反复提到它的原因。

1 · 定义：四个颜色 = 四种含义，全应用一致

ITO 青 #168a9d

进行 / 活跃

正在发生的事：running、released、ready。也是“主行动”色（Phase 0 前用它做主按钮）。

--ito: #168a9d
钙钛矿紫 #6852b8

计划 / 配置

还没发生的事：planned、draft、preparing、suggested。计划态的东西永远是紫，不会误读成进行中。

--perovskite: #6852b8
成功绿 #1e7a4d

完成 / 通过

completed、consumed、approved——已经落定、不需要你再管的记录。

--success: #1e7a4d
警示琥珀 #b66a00

等待人 / 异常

pending approval（等你批）、deviation（有偏差要看）。红 #b3261e 另有专职：失败/取消，量最少。

--amber: #b66a00

2 · 为什么它重要：一个实验记录的完整生命周期

把四色串起来看——你在列表页扫一眼，颜色直接告诉你“哪些事在等谁”：

draft→ pending approval（等你批）→ approved→ released（可开工）→ in_progress（制备中）→ completed cancelled（灰，淡出）

Phase 0 的圆点徽章用的就是这套映射；运行单里 planned=紫、running=青、 consumed=绿 也是它。颜色承担了“状态机可视化”的职责，所以任何新主题都不能把它抽掉。

3 · 眼见为实：同一张列表的两种画法

✗ 坏例子：颜色即背景（Notion/Airtable 品牌规范的纯药丸路线推到极端）
ExperimentPlanRecord
usual_v1-v1 RELEASEDCOMPLETED
usual_v1-v3 PENDING APPROVALSUGGESTED
usual_v1-v2 RELEASEDFAILED

一行六个色块，每个都在喊叫—— 这就是诊断 V3 说的“徽章彩纸”。扫一眼分不出轻重：哪行在等我？没有答案。

✓ 第 0 期做法：颜色即圆点，文字保持中性
ExperimentPlanRecord
usual_v1-v1 releasedcompleted
usual_v1-v3 pending approvalsuggested
usual_v1-v2 releasedfailed

同样的四色语义，但视觉重量只有圆点那么大。 一眼扫去：琥珀点那行在等你；其他行可以略过。这就是“一行最多一个强调色”的实际含义。

4 · 对主题选型的约束（也是我推荐保 Apple 的核心理由）

  • 必须保留：四色语义 + “圆点优先、文字中性”。这条与品牌无关，是功能。
  • Apple 主题：天然兼容——它本来就只有 #0071e3 一个交互色，状态色自成一层，零冲突。零改动。
  • Notion 主题：其规范说“核心 UI 只允许一个饱和色（#0075de）”。要保留四色语义就得打破它的 purity——可以做成“交互色用 Notion 蓝，状态色作为功能层例外保留”，但这就不再是“严格按规范”，而是又一层折中（你已经否过一次折中）。
  • 无论选谁：四色语义进 theme.ts 的 semantic 层，MUI 组件通过 token 引用，不允许组件自定义状态色。
