UI 风格参考 — 同一份数据的五种处理

范围限定在第 0 期的三块界面（实验列表 / 结果文件与 Provenance / 运行单执行卡片），数据取自演示实例的种子内容。 标签 0 是现状对照；A 为 Apple 气质的手写 CSS 方案；B/C 模拟 MUI / Ant Design 的默认观感；D 是把 MUI 主题定制成 Apple 气质的样子。 B/C/D 为手工 CSS 模拟，真实引入组件库后细节会有差异（选定后我会先用真实依赖做一个 spike 页面验证）。点击徽章/折叠块可交互。

方案新增依赖与 Apple 气质的距离能否落在第 0 期（禁改结构）一句话
0 · 现状——（IBM Plex 基础）—（问题基线）面板套面板、徽章五彩、系统值外泄、长英文时间戳（V1–V5）。
A · Apple 纯 CSS无最贴近可以，纯 CSS/组件层系统字体栈（macOS 上是 SF Pro）、细线代替描边、圆点状态；零依赖，风险最低。
B · MUI 默认@mui/material + emotion，约 +100 kB gz较远（Material）不行 — 需替换 DOM 结构，要单独立项组件/交互现成，但默认语言是 Chip 与卡片阴影。
C · AntD 默认antd + dayjs，约 +120 kB gz最远（企业后台）不行 — 同上Badge 圆点与第 0 期目标天然一致，但整体气质改动空间小。
D · MUI·Apple 主题同 B接近 A（约九成）不行 — 同上（建议第 1 期动 DOM 时再评估）主题定制后的 MUI：观感接近 A，交互行为（焦点环/键盘/过渡）由库承担。
